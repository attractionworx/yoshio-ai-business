# Yoshio AI Business

コンテンツのテーマや読者を整理し、このMacに保存するローカルWebアプリです。
ブログ・アフィリエイト記事、note、SNS、YouTubeなどの制作準備に使えます。

第1段階では入力内容の整理と保存だけを行います。AIによる文章生成、外部APIへの接続、自動投稿は行いません。APIキーや有料サービスの契約は不要です。

## 1. 起動方法

Node.js 22以上を使用します。今回の環境ではNode.js 24で確認しています。

Macの「ターミナル」を開いて、次のコマンドを1行ずつ実行してください。

```bash
cd /Users/yoshio/yoshio-ai-business
npm install --cache .npm-cache --ignore-scripts --no-audit --no-fund
npm start
```

`npm install`は初回に実行します。追加のnpmパッケージに依存せず、Node.jsの標準機能だけで動きます。2回目からはフォルダへ移動して`npm start`だけで起動できます。

起動メッセージが出たら、SafariやChromeのアドレス欄に以下を入力してください。

**http://127.0.0.1:3000**

起動中はターミナルを開いたままにします。

### 使い方

1. 「コンテンツのテーマ」を入力します（必須・200文字まで）。
2. ターゲット読者を入力します（任意・500文字まで）。
3. 媒体をブログ / note / X / Instagram / YouTubeから選択します。
4. 目的（1,000文字まで）とメモ（5,000文字まで）を必要に応じて入力します。
5. 「企画を作成」を押すと保存され、整理した内容が表示されます。
6. 「企画一覧・新規作成へ」から、保存した企画を開いたり、新しい企画を作成したりできます。

前後の空白は取り除いて保存します。未入力の任意項目は詳細画面で「未入力」と表示します。各企画は独立したファイルになり、同じテーマでも別の企画として保存されます。詳細画面を再読み込みしても追加保存されません。

### 起動できないとき

- `node`や`npm`が見つからない場合は、Node.jsが利用できるターミナルか確認してください。
- 「ポート3000が使用中」と表示された場合は、先に起動したアプリのターミナルで`Control + C`を押してから再実行してください。
- 保存や表示に失敗した場合は、ターミナルのエラーと`data/`フォルダを確認してください。データを手動編集してJSONの形式が壊れると、読み込めなくなる場合があります。削除せずバックアップを取ってから確認してください。

## 2. 終了方法

起動に使ったターミナルで **Control + C** を押します（Commandキーではありません）。
ブラウザを閉じるだけではアプリは終了しません。終了後も企画ファイルは残ります。再び`npm start`で起動すると、保存済みの企画を開けます。

## 3. ファイル構成

```text
yoshio-ai-business/
├── server.js            # 画面表示、入力の確認、ファイル保存、起動処理
├── public/
│   └── style.css        # 色・余白・スマートフォン向け表示
├── test/
│   └── server.test.js   # 保存や再表示などの自動動作確認
├── scripts/
│   └── browser-check.mjs # インストール済みChromeでフォームを実際に操作
├── data/               # 起動・保存時に自動作成（Git対象外）
│   ├── <企画ID>.json    # 1企画につき1ファイル
│   └── test-runs/       # 自動テストの検証用データ
├── package.json        # プロジェクト情報と起動コマンド
├── package-lock.json   # npmが管理する構成情報
├── .gitignore          # GitHubへ送らないファイルの設定
└── README.md           # この説明書
```

JSONは項目名と値を組み合わせたテキスト形式です。企画ID・作成日時・5つの入力項目を保存しています。データベースの設定は不要です。バックアップにはアプリを終了してから`data/`フォルダをコピーしてください。GitHubには企画データを保存しないため、Gitだけではバックアップになりません。

### 秘密情報とローカル利用

- APIキーなどの秘密情報をコードへ直接書かないでください。将来APIを追加するときは、環境変数などからサーバー側で読み込みます。
- `.env`、`.env.*`（`.env.example`を除く）、`secrets/`、秘密鍵、企画データ、npmキャッシュは`.gitignore`で除外しています。`.env.example`を作る場合はダミー値だけにしてください。
- 現段階では`.env`の読み込み処理はありません。秘密情報の入力も不要です。
- `.gitignore`はコードなどへ直接書いた秘密情報や、すでにGitへ登録済みのファイルを保護するものではありません。公開前には変更内容を確認してください。
- アプリは`127.0.0.1`だけで待ち受けます。ログイン機能はなく、このMacでの個人利用を想定しています。保存ファイルは暗号化していません。

### 動作確認

```bash
npm test
```

フォーム表示、企画保存、アプリ再起動後の再表示、改行と日本語の保存、HTMLの安全な表示、入力チェック、外部サイトからの保存拒否、非公開ファイルへアクセスできないことを確認します。テストデータは`data/test-runs/`に作成し、通常の企画一覧には表示しません。

実際のブラウザでも確認するには、Google ChromeがインストールされたMacでアプリを起動し、別のターミナルから以下を実行します。

```bash
cd /Users/yoshio/yoshio-ai-business
node scripts/browser-check.mjs
```

画面を表示しないChromeでフォームを入力してボタンを押し、保存ファイル・企画画面・一覧への掲載を確認します。「【動作確認】ブラウザからの企画作成」という企画を1件追加します。既存の企画は変更・削除しません。確認用のChromeプロフィールと結果は`data/browser-check/`に残します。普段使用しているChromeのプロフィールは使いません。

画面の`Referrer-Policy`は`same-origin`に設定しています。同じアプリへのフォーム送信で送信元を保持し、外部サイトへの参照元送信を抑える設定です。`no-referrer`にするとブラウザが送信元を`null`にして、正常なフォーム送信も安全チェックで拒否されるため変更しないでください。

## 4. 今後どこを拡張するか

小さな機能から順に追加することを想定しています。

1. **企画の編集・検索**：`server.js`の保存処理と一覧画面を拡張します。削除機能を加える際は確認画面も用意します。
2. **媒体別テンプレート**：詳細画面を作る`detailPage`に、記事構成、SNS投稿案、動画企画の項目を追加します。
3. **AIによる下書き**：専用のサーバー側ファイルを追加してAPIを呼び出します。キーは環境変数に入れ、送信する内容と料金を確認できる仕組みを用意します。
4. **書き出し**：企画や下書きをMarkdownなどにして保存・コピーできるようにします。
5. **投稿支援**：まず人が内容を確認する工程を設け、その後で必要な媒体への連携を検討します。

機能が増えた段階で、`server.js`を画面・保存・AI連携などのファイルに分けると管理しやすくなります。
