# Candidate mapping reflection v2

Legacy projection.js remains unchanged. Options without schemaVersion use the exact v1 projection; schemaVersion=2 options use projection-v2.js. Ledger envelope and intent/result types remain v1; each intent stores the versioned plan and versioned options. Unknown versions stop. Old intent replay never uses v2 projection. Existing recovery compares exact historical offer business snapshots and never writes/rolls back an offer.

Every candidate requires an explicit choice: none (nonblank reason), offer (allowed top-level target), or conversions (existing IDs). No default choice, AI mapping, conversion creation or conversionKey rewriting. Multiple IDs require explicit commonConfirmed and target/category = eligibility/eligibility, approvalConditions/approval, rejectionConditions/rejection. Names and CTA are single-target only. Reward evidence and unmapped can only be none. None does not change review decision or checking and is retained with content, citations and reason in the signed plan/audit.

V2 formal statements use imp2- + SHA256(JSON([importId,candidateId,conversionId-or-null])). IDs fit the existing 80-character contract, are deterministic, and collisions with existing items stop. Mappings record candidate, conversion, field, formal ID, source IDs, citations, usage and checkedAt. Existing source IDs/reuse checks remain. A candidate that has been reflected by v1 or v2 cannot later reflect again, even to a new destination. A none choice is an audited choice for this operation only and does not consume the candidate.

Options, import/offer snapshot hashes, revisions, all candidate decisions and mapping are included in preview hash and HMAC confirmation. Every new v2 preview replaces the previous v2 confirmation for that import within the service. Opening the v2 selection screen also invalidates the previous v2 confirmation. Restart invalidates confirmations through the existing per-process signing secret. Submitted selection revisions are validated; no auto-refresh/merge. Preview page is read-only; selecting new mappings requires returning to the selection screen. Unsaved/unsubmitted intent cannot be observed by the server.

V2 preview preparation is POST /offer-imports/:id/reflection-v2 but performs no durable writes. GET chooses the offer and renders native forms. Approval uses existing POST /commit with explicit checkbox. Field allowlists, Origin/Host/CSP/no-store remain. 512,000-byte form cap, 400,000-character v2 signed payload cap, <=200 candidates, <=200 existing conversions and <=1,000 total selected destinations. Legacy signed payload stays capped at 20,000 characters. Full evidence is accessible through native details; JS is not required.

All-none plans may be approved: append intent and committed result at the existing offer revision without an offer update. Result-save uncertainty leaves an unresolved intent and requires explicit recovery; the planned unchanged snapshot is checked against exact history. Plans with formal changes use the unchanged offer update/intent/result flow. Ledger validation and maintenance use the version dispatcher. Existing backup envelopes remain unchanged because the commit envelope stays v1. Mixed histories and audit-only results require regression coverage.

Extraction follow-up (not part of implementation): propose distinct groups for distinct conversion points in a document; distinguish common conditions, specific conditions and cross-conversion reward rules. Version any new profile/contract; do not modify fixed profiles, artifacts or originals. AI proposals never replace human mapping/approval. Shared reward precedence stays internal, unstructured and excluded here.
