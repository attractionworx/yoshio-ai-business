# Target-disjoint extraction: execution v5

Wire v3 retains the candidate object fields and ordered candidates/evidence arrays. Each of thirteen target-specific branches is a complete object under nested anyOf. Targets are disjoint singleton enums; there is no fallback branch. Category, purpose, usage and conversionKey constraints exactly reflect the unchanged internal v1 candidate validator, including generic categories on targets without a fixed mapping. Wire validation rejects incompatible combinations before quote lookup; it never supplies or rewrites candidate values.

All evidence still consists of documentId, blockId and quote. Exact search only within the specified block, overlapping occurrence detection, document-origin UTF-16 offsets and end-exclusive ranges retain algorithm v1 semantics. Zero/nonunique matches stop. After conversion, the unchanged internal v1 schema and validator run. The v3 inverse strips only generated offsets, preserves every other value/order, and restores wire schemaVersion 3. Runtime must equal the original wire; audit reconstructs the wire, binds recorded usage to responseHash and replays resolution against the immutable input.

Processing contract quote-resolution-v2 pins wire v3, internal v1, resolver semantics block-exact-unique-utf16-v1, inverse strip-offsets-wire-v3-v1 and exact implementation/validator hashes. Execution/ledger v5 retains the v4 record shape and result binding fields, with immutable profile snapshot v3 and the new processing contract. Both ordinary extraction and explicit configuration upgrades create v5 under this contract. Snapshot data never executes code. processing-registry selects only application-owned implementations by exact version/hash. evidence-resolution.js and execution-v4-contract.js remain byte-for-byte unchanged for legacy v4 audit; new implementations reside in separate files. Unknown version/hash, wrong snapshot/execution/processing pair and tampering stop.

Historical profiles and records are not rewritten. Profile snapshot v2's static schema now enumerates both exact known v4 public profiles, aligning the existing runtime registry without admitting unknown profiles. Snapshot v3 enumerates the new registered public profile and the strict fake-only profile shape. Internal offer/import/artifact schemas and all candidate acceptance conditions remain unchanged. Source/configuration lineage, terminal eligible failure leaf restrictions, duplicate refusal, ancestor configuration exclusion, one child per source and two human approvals retain their previous meaning. Preparation has no fee reservation; sending separately reserves the destination estimate. Past usage/cost/diagnostics remain immutable.

The shared budget, durable sending ownership, no-double-send, unknown reservation retention and explicit local save recovery are unchanged. Invalid wire responses retain only existing fixed diagnostics, responseHash and known usage; no failed response/quote/candidate values or indices are saved. Failed resultBinding stays null. No automatic repair, resend, activation, migration or restore is added.

Mixed ledger v5 validates v1-v4 on their own record/transition paths and checks lineage using original rows. Maintenance separates historical integrity from current send permission and replays each processing version. Backup manifest v5 declares execution 5, snapshot 3, wire 3 and processing resolution 2; backed-up mixed rows retain their own versions. Manifests 1-4 remain readable. Dry-run validates without restore or store mutations. Readers predating v5 cannot read v5 ledgers; downgrade is unsupported.

Fictional fixtures/fake providers test the full 4680 target/category/purpose/usage/conversionKey combinations against the existing validator, disjoint branches, supported strict schema keywords, no candidate correction, exact quote resolution, roundtrip and binding tampering, mixed histories/profiles/backups, concurrency/restart/partial save/unknown and downstream boundaries. External connections are guarded; real Provider schema acceptance is not proven by fake-provider tests. Structurally valid but semantically wrong target selection still requires human review. Hash bindings detect inconsistency, not coordinated rewriting of an unsigned history or proof of Provider provenance.
